# 功能设计文档技能

当前版本：5.0.2（2026-10-27）。技能名称保留 `trs-prd-writer`，默认供业务人员阅读，适用于追溯及其他业务系统。

支持三种输入：已确认的需求研讨、原型及补充说明、当前代码。新建、补充和核对均沿用同一套业务写作规范。简单功能简写，复杂流程按对象或阶段展开，不省略改变业务结果的规则。

## 使用

将本目录作为完整技能包，复制到所用工具的技能目录并保留 `references/`。按该工具方式刷新技能；可以显式调用 `$trs-prd-writer`，也可提出：

- “刚才已经讨论确认，请整理成给业务看的功能设计文档。”
- “根据这个原型和补充规则完善功能说明，不重做原型。”
- “根据指定仓库的当前代码还原功能文档，保留未核实事项。”

默认输出本地 Markdown；仅需要保存依据、冲突或未决事项时增加 `.notes.md`。需要 Word、PDF 或云端文档时复用已有工具，按请求另行处理。

Grill、带文档的研讨、原型和开发规格均优先复用使用者已有技能，名称以环境清单为准。它们是可选协作能力；本包没有特定项目、个人目录或服务平台的必装依赖。只有本技能也能完成资料充分的文档任务。

## 维护

本包由当前工作区的 `.agents/skills/trs-prd-writer/` 生成，这是独立版唯一维护源。修改源文件后运行 `python 工具/build_publish_skill.py`；发布目录是生成副本，不单独改写。源文件和发布文件内容一致，发布包可离开维护工作区单独安装。

| 文件 | 职责 |
|---|---|
| `SKILL.md` | 输入选择、按需连接其他技能、更新和交付步骤 |
| `references/requirements.md` | 承接确认需求 |
| `references/prototype.md` | 区分原型呈现与补充规则 |
| `references/code.md` | 追踪现状、保留依据和限制 |
| `references/writing.md` | 共用业务写法和交付检查 |
| `references/template.md` | 唯一新建正文骨架 |
| `evals/` | 可重复试用题目及示例代码，不是实际项目规则 |

`npm test` 检查包内链接、编码、可加载性和独立性；它不能证明模型成稿质量。历史文档与旧发布包保存在维护工作区的 `99_归档/`，不作为当前执行规则。

项目专用版本由相应项目维护；本独立版与它共享设计原则，不引用它的文件或要求安装它。AI生成结果仍需业务人员审阅。
