# 代码驱动原型设计（从真实代码反推界面设计章节）

> 适用：手上有可运行的前后端代码，要写或补功能设计文档的「界面设计及交互」章节。
> 与另外两个原型类 skill 的区别：**它们产出可运行的前端代码，本模式产出文档章节内容**。
> （`space-image2proto` 截图→HTML；`pm-url2proto` / `space-url2proto` URL→Next.js 原型。本模式不产出可运行代码。）

## 1. 为什么代码优先

代码是事实，原型只是呈现。已有可运行代码时，**先反推再美化**，比先画原型再对齐代码少一轮返工。
反推出的东西天然带证据坐标（`文件:行号`），审查时直接可验。

## 2. 入口：先找真实生效的页面

一个前端页面只有满足之一才算真实生效（完整判据 → `trs-evidence` §2）：

1. 被路由配置的 `component` 指向
2. 被业务 `.vue` / `.ts` import 并在模板中渲染
3. 引用方不是 `components.d.ts` 这类自动类型声明

**只从真实生效的页面反推。** `components/` 下未接线的同名子组件是遗留物，画进去就是文档臆造。

入口通常是 `index.vue`（列表页）+ `detail.vue` / `field.vue`（详情/字段页）。

## 3. 四类要素的抽取口径

| 要素 | 从哪抽 | 落到文档哪一节 |
|---|---|---|
| **字段** | 表单 `el-form-item` 的 `label` + `rules`；列表 `el-table-column` 的 `label` | 数据项表（12 列） |
| **按钮** | 模板里的 `el-button` 文案 + `@click` 处理函数名 | 界面设计及交互 / 操作说明 |
| **校验** | `:rules` 定义 + 后端校验返回串（逐字抄） | 数据项表「校验规则」「报错文案」两列 |
| **状态** | 快码/枚举（按套比、过滤已删除行） | 状态机小节（多套各自成节） |

抽取一律带 `文件:行号`。没有坐标的字段不写进文档。

## 4. 反推 → 原型 → 章节 三步

1. **反推骨架**：按「查询区 → 列表 → 操作列 → 弹窗/抽屉 → 详情页签」五段列要素。
   骨架取自代码的 DOM 结构，不取自「用户先点什么再点什么」的叙事线 —— 叙事自洽 ≠ 要素穷举。
2. **画原型**：把骨架转成 HTML 原型或截图，供评审用。
   纯文字 ASCII 流转图只用于草稿，正式文档用 HTML 或截图（`prototype-driven.md` 同规）。
3. **写章节**：§6.x.1 界面设计及交互 = 原型图 + 要素说明；字段落数据项表；状态落状态机小节。

## 5. 三个必踩的坑

- **弹窗字段 ≠ 列表字段**：查询区、编辑弹窗、列表列、详情页签是四处不同上下文，抽字段前先确认它在哪一处。
- **后端独有的能力**：纯后端端点、定时任务、调度引擎在前端 grep 不到，必须补扫后端，否则整块漏写。
- **反推完要回头穷举一遍**：落笔 ≠ 覆盖。实证：外部调度第一版补写后回头穷举，又抓到 5 处。

## 6. 与其它模式的接力

```
代码驱动（反推骨架 + 要素）
      ↓
原型驱动（做成可评审的 HTML 原型）
      ↓
传统需求沟通（补齐代码里没有的业务口径）
```

## 7. 完成判据

- 每个字段 / 按钮 / 校验 / 状态都带 `文件:行号`。
- 骨架五段（查询区/列表/操作列/弹窗/详情页签）逐段核过，没有整段跳过。
- 后端扫描源覆盖：Controller / Service / 枚举 / Mapper / 定时任务 / 快码。
- 反推完成后回头穷举过一遍。
