## 3. 数据项表格列定义（两套 12 列，按交付模式取用）

> ⚠️ **本项目存在两套都叫「12 列」的表头，列名不同，不可混用。** 取用规则见下表；拿不准先看交付模式。

| 交付模式 | 用哪套 | 列头 |
|---|---|---|
| `CLIENT-FINAL`（客户终稿） | **客户终稿 12 列**（SSOT 在 `trs-spec-style` §5） | 字段名 / 字段标识 / 字段类型 / 是否必填 / 是否唯一 / 默认值 / 取值来源 / 展示形式 / 校验规则 / 报错文案 / 备注 / 变更记录 |
| `INTERNAL`（内部评审） | **开发实现 12 列**（本节原文） | 序号 / 字段名 / 控件类型 / 数值类型 / 长度 / 必输 Y/N / 新增 Y/N / 编辑 Y/N / 值列表说明 / 默认值 / 校验规则 / 其他说明 |

两者差异不是笔误，是用途不同：客户终稿列面向**业务验收**（含报错文案、变更记录、取值来源），开发实现列面向**研发落地**（含长度、控件类型、新增/编辑可见性）。

### 3.1 `INTERNAL` 模式：开发实现 12 列

```markdown
> 📌 **数据项 12 列 / 字段类型 / 控件类型的唯一权威**：`trs-spec-style/reference/data-item-spec.md`（纪律层 SSOT）。本处为速查或示例，两套口径勿混用。
| 序号 | 字段名 | 控件类型 | 数值类型 | 长度 | 必输 Y/N | 新增 Y/N | 编辑 Y/N | 值列表说明 | 默认值 | 校验规则 | 其他说明 |
```

- 任何文件不得使用简写列名（如"控件/类型"拆分或"值列表"省略"说明"）。
- 引用列数时一律写作 **12 列**。

### 3.2 `CLIENT-FINAL` 模式：客户终稿 12 列

```markdown
| 字段名 | 字段标识 | 字段类型 | 是否必填 | 是否唯一 | 默认值 | 取值来源 | 展示形式 | 校验规则 | 报错文案 | 备注 | 变更记录 |
```

- 字段类型一律中文命名（文本 / 长文本 / 数字 / 小数 / 日期 / 日期时间 / 布尔 / 下拉单选 / 下拉多选 / 枚举 / 附件 / 图片），不写数据库类型。
- 报错文案取真实前端 / 后端返回串，走 `trs-evidence` L3 级。
- 完整填写规则 → `trs-spec-style/reference/data-item-spec.md`。
