# TRS PRD Skill 规格定义（SSOT）

> 本文档是本 Skill 的**唯一事实源（Single Source of Truth）**。
> 所有其他文件（SKILL.md、document-structure.md、templates.md、examples.md、README.md、CHECKLIST_V2.0.md、testing/*）中的章节编号、数据项列定义、版本号、枚举值，若与本文档冲突，**一律以本文档为准**。
> 冲突无法自判时，Agent 应上报而非自行选择。

## 2. 文档章节编号（1-11 体系）

| 章号 | 章节名 | 必填性 |
|------|--------|--------|
| 1 | 文档控制 | 必填 |
| 2 | 目录 | 自动生成 |
| 3 | 前言 | 必填 |
| 4 | 问题定义与用户画像 | 必填 |
| 5 | 概述 | 必填 |
| 6 | 总体设计 | 必填 |
| 7 | 详细设计 | 必填 |
| 8 | 非功能性需求 | 建议 |
| 9 | 发布计划与成功度量 | 可选 |
| 10 | 协作与版本管理 | 可选 |
| 11 | 未解决问题/已解决问题 | 可选 |

> 引用章节号时必须使用上表。例如"输出门禁"中的 `8章非功能需求` 指上表第 8 章。

---

## 3. 数据项表格列定义（12 列，统一列名）

```markdown
| 序号 | 字段名 | 控件类型 | 数值类型 | 长度 | 必输 Y/N | 新增 Y/N | 编辑 Y/N | 值列表说明 | 默认值 | 校验规则 | 其他说明 |
```

- 任何文件不得使用简写列名（如"控件/类型"拆分或"值列表"省略"说明"）。
- 引用列数时一律写作 **12 列**。

---

## 4. 接口契约（业务视角）

操作总览表统一为 **5 列**：

```markdown
| 序号 | 操作名称 | 触发时机 | 业务含义 | 业务校验规则 |
|------|---------|---------|---------|-------------|
```

- 不展示 HTTP 方法、URL 路径、原始 JSON、技术响应码、数据库表结构。

## 5. ID 体系

| 前缀 | 含义 |
|------|------|
| F-xx | 功能项 |
| AC-xx | 验收标准 |

| NFR-xx | 非功能需求 |
| RISK-xx | 风险项 |
| ASSUME-xx | 假设项 |

## 6. 枚举值

| 枚举 | 取值 |
|------|------|
| 风险等级 | 高 / 中 / 低 |
| 优先级 | 高 / 中 / 低 |
| 来源类型 | 原型 / 用户确认 / 假设 / 推导 |
| 文档状态 | 编制中 → 待审核 → 已审核 → 已发布 |

---

## 7. 冲突仲裁顺序

```
spec.md > SKILL.md > document-structure.md > templates.md > examples.md
```

当不同文件对同一事实（章节号、列数、版本、枚举）表述冲突时，按上述顺序取高优先级者为准，并在交付物中标注冲突已按 SSOT 仲裁。
