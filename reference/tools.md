## 工具1: SMART指标检查器

用于验证成功指标是否符合SMART原则。

### 检查清单

| 原则 | 检查项 | 示例 |
|------|--------|------|
| **S (Specific)** | 指标是否清晰明确？ | ✅ "查询时间从10分钟缩短到2分钟"<br>❌ "提升查询效率" |
| **M (Measurable)** | 能否量化？如何统计？ | 询问：用系统统计还是人工统计？ |
| **A (Achievable)** | 目标是否现实？ | 询问：有无类似案例？技术可行性如何？ |
| **R (Relevant)** | 是否与业务目标相关？ | 询问：这个指标对业务有什么价值？ |
| **T (Time-bound)** | 有明确的时间框架吗？ | ✅ "上线后1个月内达到目标" |

### 使用方法

```markdown
对于每个成功指标，逐项检查：
1. [ ] S - 具体明确吗？
2. [ ] M - 可以衡量吗？
3. [ ] A - 可以达成吗？
4. [ ] R - 与目标相关吗？
5. [ ] T - 有时间限制吗？
```

## 工具2: 风险评估矩阵

用于评估风险等级并制定缓解措施。

### 风险等级计算

| 影响程度 \ 发生概率 | 高 | 中 | 低 |
|-------------------|----|----|----|
| **高** | 🔴 高风险 | 🟠 中高风险 | 🟡 中风险 |
| **中** | 🟠 中高风险 | 🟡 中风险 | 🟢 低风险 |
| **低** | 🟡 中风险 | 🟢 低风险 | 🟢 低风险 |

### 缓解措施优先级

| 风险等级 | 措施 |
|---------|------|
| 🔴 高风险 | 必须制定详细的缓解计划，定期跟踪 |
| 🟠 中高风险 | 制定缓解措施，安排责任人 |
| 🟡 中风险 | 制定基本缓解措施 |
| 🟢 低风险 | 记录在案，定期回顾 |

### 风险识别清单

**技术风险：**
- [ ] 性能风险（数据量大导致查询慢）
- [ ] 集成风险（依赖其他系统接口）
- [ ] 安全风险（敏感数据泄露）
- [ ] 技术选型风险（框架/工具不成熟）

**业务风险：**
- [ ] 用户接受度风险（不习惯新流程）
- [ ] 业务流程风险（影响现有业务）
- [ ] 数据质量风险（数据不准确）

**依赖风险：**
- [ ] 依赖的系统/功能
- [ ] 依赖的数据
- [ ] 依赖的资源（人力/时间）

## 工具3: 用户旅程图模板

用于描述用户的完整使用体验。

```markdown
| 阶段 | 感知 | 发现 | 评估 | 使用 | 满意/不满 |
|-----|------|------|------|------|-----------|
| 关键动作 | 听说有新功能 | 查找功能入口 | 了解功能说明 | 完成操作 | 评价功能 |
| 情感曲线 | 😐 | 🙂 | 🤔 | 😊 | 😊/😟 |
| 痛点 | 不知道有这个功能 | 找不到入口 | 说明不够清楚 | 操作复杂 | 某些功能不满足需求 |
| 机会点 | | 优化入口位置 | 提供引导教程 | 简化操作流程 | 收集反馈改进 |
```

### 使用场景

- 功能涉及多个用户角色时
- 需要分析用户体验痛点时
- 设计新功能或优化现有功能时

## 工具4: 问题定义模板（5W1H）

### 完整模板

```markdown
## 核心问题定义

### Why (为什么)
- **业务背景：** [描述业务背景]
- **核心问题：** [1-2句话清晰陈述]
- **影响范围：** [哪些用户/业务受影响]
- **紧迫性：** [为什么现在必须解决]

### What (是什么)
- **要解决的问题：** [具体描述]
- **核心需求：** [主要需求点]

### Who (谁)
- **提出者：** [业务部门/领导/客户]
- **使用者：** [谁会使用]
- **影响者：** [谁会受影响]

### When (何时)
- **使用场景：** [什么时候使用]
- **使用频率：** [每天/每周/偶尔]
- **期望时间：** [什么时候上线]

### Where (在哪里)
- **使用系统：** [TRS系统/ERP等]
- **使用设备：** [PC/平板/手机]

### How (如何)
- **核心解决方案：** [如何解决]
- **替代方案及选择原因：** [为什么选择当前方案]
```

### 快速版本

```markdown
## 5W1H快速定义

| 维度 | 内容 |
|------|------|
| Why | [为什么要做？痛点是什么？] |
| What | [要做什么？核心功能是什么？] |
| Who | [谁使用？谁提出？谁受影响？] |
| When | [什么时候用？使用频率？] |
| Where | [在哪个系统用？什么设备？] |
| How | [怎么解决？有无替代方案？] |
```

## 工具5: 成功指标模板

### 详细模板

```markdown
| 指标名称 | 指标说明 | 基线值 | 目标值 | 衡量方法 | 时间周期 | 责任人 | 达标标准 |
|---------|---------|-------|-------|---------|---------|-------|---------|
| 查找效率 | 平均查询时间 | 10分钟 | <2分钟 | 系统统计 | 上线后1个月 | 数据分析师 | 达成率>90% |
| 错误率 | 错误次数/总操作数 | 20% | <5% | 系统统计 | 上线后1个月 | 质量经理 | 达成率>90% |
| 用户满意度 | 问卷评分(1-5分) | 3.5分 | >4.5分 | 用户问卷 | 上线后3个月 | 产品经理 | 达成率>80% |
```

### 简化模板

```markdown
| 指标名称 | 基线值 | 目标值 | 衡量方法 | 时间周期 |
|---------|-------|-------|---------|---------|
| | | | | |
```

### 使用说明

1. 基线值：功能上线前的当前状态
2. 目标值：期望达到的状态（需符合SMART原则）
3. 衡量方法：如何统计/测量这个指标
4. 时间周期：上线后多久检查
5. 责任人：谁负责跟踪这个指标
6. 达标标准：达成率/覆盖率要求

## 工具6: 风险评估矩阵模板

```markdown
| 风险ID | 风险类别 | 风险描述 | 影响程度 | 发生概率 | 风险等级 | 缓解措施 | 责任人 | 状态 |
|-------|---------|---------|---------|---------|---------|---------|-------|------|
| R001 | 技术风险 | 数据量过大导致查询缓慢 | 高 | 中 | 🟠 中高风险 | 分页+索引优化 | 技术负责人 | 进行中 |
| R002 | 业务风险 | 用户不适应新流程 | 中 | 高 | 🟠 中高风险 | 提前培训+操作手册 | 产品经理 | 计划中 |
| R003 | 依赖风险 | 依赖XX系统的接口未完成 | 高 | 低 | 🟡 中风险 | 调整优先级或寻找替代方案 | 项目经理 | 监控中 |
```

### 填写说明

| 字段 | 说明 |
|------|------|
| 风险ID | 唯一标识，如R001 |
| 风险类别 | 技术风险/业务风险/依赖风险 |
| 风险描述 | 具体描述风险内容 |
| 影响程度 | 高/中/低 |
| 发生概率 | 高/中/低 |
| 风险等级 | 根据矩阵自动计算 |
| 缓解措施 | 如何降低风险 |
| 责任人 | 谁负责跟踪 |
| 状态 | 进行中/计划中/监控中/已解决 |

## 工具9: 发布计划模板

```markdown
| 阶段 | 时间 | 范围 | 目标 | 退出标准 | 责任人 | 状态 |
|-----|------|-----|------|---------|-------|------|
| 试点阶段 | 上线后1周 | 部分用户 | 验证功能稳定性 | 无严重bug、用户反馈良好 | 运营经理 | 计划中 |
| 推广阶段 | 上线后1个月 | 全部用户 | 全面推广使用 | 用户满意度>4分、使用率>80% | 产品经理 | 未开始 |
| 优化阶段 | 上线后3个月 | 全部用户 | 持续优化 | 根据反馈迭代优化 | 产品经理 | 未开始 |
```

### 上线方式选择

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| 分阶段上线 | 新功能、重大变更 | 风险可控 | 周期长 |
| 一次性上线 | 小功能、紧急修复 | 周期短 | 风险集中 |
| A/B测试 | 优化类功能 | 数据驱动 | 复杂度高 |
