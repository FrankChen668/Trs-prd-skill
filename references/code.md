# 从代码还原现有功能

还原的是指定版本和范围内观察到的实现，不等同于生产系统已启用、业务预期正确或用户已经验收。只读分析不要求先启动应用；确需运行核对时按项目规则执行，并如实说明未运行的限制。

## 先固定范围与依据

读取用户指定功能、相关领域资料及前后端实际文件。按用户给出的路径及项目说明定位仓库，记录分支/提交及相关本地修改；非Git目录注明版本未知。历史分析和生成索引只是找入口的线索，引用前核对当前文件；不把历史扫描计数当作本次覆盖范围。

在配套记录中用轻量对照保存“正文小节或规则 → 来源路径:行号及符号 → 已观察/未验证/冲突”。代码、DDL、OpenAPI、菜单、字典和人工确认分别标识来源及版本，缺失、过期或环境不对应的资料保持未验证。

## 沿功能追踪，按需补充

| 需要确认 | 核对位置及边界 |
|---|---|
| 页面确有入口 | 菜单数据、动态/静态路由、业务组件调用与页面。只搜不到静态引用不判废弃；只有类型声明也不能证明启用 |
| 操作能完成什么 | 页面事件 → 请求 → 网关/服务入口 → 实际业务处理 → 数据或外部调用 → 返回结果。按钮或Controller单独存在不足以证明闭环 |
| 字段和校验 | 查询、列表、新增、编辑、详情分别核对；前端限制与后端限制分开观察，避免把数据库长度直接当业务约束 |
| 状态及允许操作 | 分对象核对实际处理逻辑、枚举、同套字典和状态配置；选项存在不等于所有流转均可执行 |
| 权限与数据范围 | 按使用者项目的权限约定核对菜单、按钮、接口和实际数据过滤。按钮隐藏不等于接口已限制 |
| 后台能力 | 对本次范围涉及的调度、消息、通知、文件处理和报表补查后台入口，不强行给无页面功能编造页面 |

字段、文件、状态或跨服务链路涉及专项时，读取使用者项目中对应的详细规则。只扫描与本次功能有关的范围；看不清关系时扩大追踪，不机械遍历全部仓库。

字典或快码按实际类别和关联键匹配，核对有效/删除标记及读取关系，不跨任务类型合并同名状态；查实际定义及调用，不能凭字段名猜关系。代码与配置有冲突时记录不同结果，不用一张固定“证据等级表”覆盖实际执行逻辑。

## 翻译为业务行为

- 正文写操作条件、处理规则、状态变化和结果；数据库表名、方法名、接口路径及代码坐标留在配套记录。
- 汇总字段校验时逐项对照，不能把“英译字段未校验”写成“名称及英译均未校验”；确有前后端差异时保留差异，不用笼统句子覆盖已核实规则。
- 正常、关键失败、批量部分成功、覆盖/删除、取消及通知只写实际核对到的行为；未看到重试实现时不添加自动重试。
- 内部状态用可核对的业务名称。任务级、文件级、下载级等分别说明，不强行合并；动态配置的可用动作注明其受配置影响。
- 只在本次范围的入口与处理关系均核对后描述为已观察到的功能。菜单是否启用或环境配置未核对时，不宣称用户当前一定可用。
- 搜索零命中只说明尚未定位到；记录查找范围和缺口。已有需求或旧文档记载的行为不能据此直接删除，也不能继续写成已实现。

## 完成条件

按本次功能清单回看：实际入口、页面动作、关键字段、状态规则及相关后台能力均已核对或列明缺口；每个重要现状结论能回到依据。核心链路有断点时交付已核实部分和草稿限制，不宣称完整现状说明。代码问题另记，不为使文档吻合而修改业务代码。
