# 数据项表与字段类型 · 完整定义

> 本文件是 `trs-spec-style`（纪律层）的自持 reference。此前 §5 / §10 指向
> `../trs-prd-writer/reference/requirements-discovery.md` —— 纪律层反向指向编排层，且那边存的是**另一套 12 列**，与本 skill §5 打架。指针已断，权威定义迁至本文件。

## 一、数据项表 12 列（唯一权威，CLIENT-FINAL）

```
字段名 / 字段标识 / 字段类型 / 是否必填 / 是否唯一 / 默认值 /
取值来源 / 展示形式 / 校验规则 / 报错文案 / 备注 / 变更记录
```

12 列一个都不能少。缺列 = 该数据项设计不完整，不是"简化了更好读"。

## 二、字段类型中文命名（唯一权威）

```
文本 / 长文本 / 数字 / 小数 / 日期 / 日期时间 / 布尔 / 下拉单选 / 下拉多选 / 枚举 / 附件 / 图片
```

写文档一律用上表的中文名，不写 `VARCHAR` / `INT` / `DATETIME` 这类数据库类型。

## 三、⚠️ 与旧口径 12 列的冲突（勿混用）

`trs-prd-writer/reference/requirements-discovery.md:58` 另存一套列头：

```
序号 | 字段名 | 控件类型 | 数值类型 | 长度 | 必输 Y/N | 新增 Y/N | 编辑 Y/N | 值列表说明 | 默认值 | 校验规则 | 其他说明
```

两套列头**不是同一件事**：本文件的是**客户终稿口径**（含报错文案、变更记录，无数据库类型）；
旧的是**开发实现口径**（含长度、控件类型、新增/编辑可见性）。

- **CLIENT-FINAL 一律用本文件第一节的 12 列。**
- 旧的仅供 `INTERNAL` 模式下与开发对齐字段实现时参考，**不得出现在客户终稿**。
- 两套都写在一张表里 = 列数对不上、口径打架，一律退回。

## 四、INTERNAL 模式补充（新增/编辑列填写规则）

仅 `INTERNAL` 模式、使用旧口径列头时的填写规则：

- 只读页面（详情页、查询结果页）：新增=N，编辑=N
- 新建表单：新增=Y，编辑=N
- 编辑表单：新增=N，编辑=Y（或 Y/灰显）
- 创建后不可改：新增=Y，编辑=N（备注写"创建后只读"）

## 八、用词裁决（委托人 Frank 裁决，2026-09-21）

**裁决人：Frank（委托人）。** 此前本节由执行者代记，未挂裁决人；现补记并据此全量落地。

| 场景 | 用词 | 禁止 |
|---|---|---|
| 字段类型（客户终稿 / 功能设计正文） | 文本 / 数字 / 小数 / 布尔 | `VARCHAR` / `INT` / **`字符`** / **`数值`** |
| 控件类型（开发实现表） | 数值（与"文本"控件并列） | — |
| 长文本 | 长文本 | `TEXT` / `CLOB` |

「数值」与「数字」同名不同层：控件类型用「数值」，字段类型用「数字」，二者不冲突。
「字符」只作**长度单位**（`最多50字符` / `≤1024 字符`）与列名 `数值类型` 的构成语素，不作字段类型取值；
`字符(200)` 记法仅允许出现在 §五 的开发对齐表内，客户终稿与功能设计正文一律写「文本」+ 长度另列。
